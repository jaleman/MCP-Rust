Media Registry — Topic-Based Metadata Search

Refactor step 15 KUKA MCP Server in Rust

Why a separate Media Registry is needed

The KUKA knowledge server extracts plain text and PDF manuals into markdown chunk bundles for full-text search. However, operational assets like video demonstrations, electrical schematics, and print sheets are non-text media. Mixing these binary or visual assets into the document extraction pipeline produces low-quality text extractions or fails entirely.

The media registry introduces a separate layer that indexes media assets by topic, keywords, MIME type, and resource URI without cluttering the document search index.

Data Model and Registry JSON

Media metadata files reside alongside media asset folders (e.g. kuka-movies/index.json and kuka-prints/index.json). Each index uses a unified JSON schema: 

[
  {
    "id": "charger-schematics-ady6102",
    "title": "Charger Schematics A.70.ADY610250008-ADY6102",
    "type": "print",
    "topic": "electrical",
    "keywords": ["electrical", "charger", "schematic", "power", "cabinet"],
    "mimeType": "application/pdf",
    "folder": "kuka-prints",
    "filename": "Charger Schematics - A.70.ADY610250008-ADY6102.pdf",
    "uri": "kuka://media/kuka-prints/Charger Schematics - A.70.ADY610250008-ADY6102.pdf",
    "description": "Electrical charger schematic print sheet."
  }
]

Rust implementation vs Java equivalent

In Rust, MediaItem derives Serde's Serialize and Deserialize traits with rename_all = "camelCase", translating between JSON field names and idiomatic Rust struct fields.

Rust MediaItem & Registry Filter:

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct MediaItem {
    pub id: String,
    pub title: String,
    #[serde(rename = "type")]
    pub media_type: String,
    pub topic: String,
    pub keywords: Vec<String>,
    pub mime_type: String,
    pub folder: String,
    pub filename: String,
    pub uri: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub description: Option<String>,
}

pub fn list_media(
    &self,
    topic: Option<&str>,
    keyword: Option<&str>,
    media_type: Option<&str>,
) -> Vec<MediaItem> {
    self.items
        .iter()
        .filter(|item| {
            if topic.as_ref().is_some_and(|t| !item.topic.to_lowercase().contains(t)) {
                return false;
            }
            if media_type.as_ref().is_some_and(|m| !item.media_type.to_lowercase().contains(m)) {
                return false;
            }
            if let Some(ref k) = keyword {
                let matches_keyword = item.keywords.iter().any(|kw| kw.to_lowercase().contains(k))
                    || item.id.to_lowercase().contains(k)
                    || item.title.to_lowercase().contains(k)
                    || item.topic.to_lowercase().contains(k)
                    || item.description.as_ref().is_some_and(|d| d.to_lowercase().contains(k));
                if !matches_keyword {
                    return false;
                }
            }
            true
        })
        .cloned()
        .collect()
}

Java equivalent (Jackson + Stream API):

@JsonIgnoreProperties(ignoreUnknown = true)
public class MediaItem {
    public String id;
    public String title;
    @JsonProperty("type")
    public String mediaType;
    public String topic;
    public List<String> keywords;
    public String mimeType;
    public String folder;
    public String filename;
    public String uri;
    public String description;
}

public List<MediaItem> listMedia(String topic, String keyword, String mediaType) {
    String t = topic != null ? topic.toLowerCase().trim() : null;
    String k = keyword != null ? keyword.toLowerCase().trim() : null;
    String m = mediaType != null ? mediaType.toLowerCase().trim() : null;

    return items.stream()
        .filter(item -> t == null || item.topic.toLowerCase().contains(t))
        .filter(item -> m == null || item.mediaType.toLowerCase().contains(m))
        .filter(item -> k == null || matchesKeyword(item, k))
        .collect(Collectors.toList());
}

MCP Tool Surface

The server exposes two new tools to clients:

  • list_media: queries media assets matching a topic, keyword, or type filter.
  • get_media: retrieves exact metadata for a specific media asset by ID or keyword.
